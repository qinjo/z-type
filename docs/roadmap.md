# Roadmap：M0 → M7

每个里程碑的验收标准统一为：**能演示的一件具体事**，而不是"代码写完了"。里程碑按依赖顺序排列，除 M6 外均以 macOS 为主战场。

| # | 里程碑 | 产出 | 验收标准（可演示） | 预估 |
|---|---|---|---|---|
| M0 | 骨架 | monorepo、CI、`rime-kit` 写回引擎雏形、Tauri GUI 壳（10 页占位）、双端上游子树接入 | `cargo test` 绿；`pnpm build` 绿；macOS 上 `git subtree pull` 后的 Squirrel 能原样编出可安装包；GUI 在 macOS 打开并显示 10 个页面 | 3–4 天 |
| M1 | 只读探查 + 部署 + 快照 | `get_env_info` / `scan_profile` / `deploy` / `list_snapshots` / `create_snapshot`；内嵌 librime；部署锁 | 打开 GUI → 看到本机真实方案列表、默认方案、共享目录 → 点"部署"成功并生成 `build/`；点"快照"后能在历史里看到 | 4–6 天 |
| M1.5 | 首启接管 | 扫描 → 备份 → 文件清单确认 → 接管；多 profile | 在干净机器（或复制一份 `~/Library/Rime`）上走完接管流程；被修改的文件在确认页逐条列出；拒绝则不做任何写入 | 2–3 天 |
| M2 | 主题 | 统一 Theme 模型 + 双端编译器；内置 4 套预设；实时预览 | 改背景色/圆角/字体/横竖排 → 保存 → 候选窗立即变化；导出主题 JSON 后换机导入还原；契约测试断言 `build/` 里字段值正确 | 3–5 天 |
| M3 | 方案与按键 | 方案启停、默认方案、候选数、翻页键、中英/简繁切换热键 | 关掉一个方案后它从候选方案列表消失；改翻页键后真的生效；改完全部落在 `default.custom.yaml`，手写注释未丢 | 2–3 天 |

| M6 | Windows 移植 | Weasel fork 接入、主题 Windows 编译、reload 走 WeaselDeployer、NSIS 打包 | 在 Windows 11 上安装 → 打字 → 在 GUI 改主题/键位 → 点应用后候选窗变化（无需重启） | 5–8 天 |

## 关键路径与风险

- M1 的内嵌 librime 是整个项目第一个技术风险点：绑定、`LIBRIME_LIB_DIR`、动态库签名、部署锁。若 3 天内跑不通，先退到"只封装 `rime_deployer` 命令行"保证 M1.5 可交付，再回头补内嵌。
- M2 的契约测试需要 `build/` 产物；若 Windows 上难以自动化，Windows 侧契约测试降级为手工。
- M6 的难点是 WeaselDeployer 调用与 maintenance 生命周期，预留时间。
- 全部里程碑都受"外壳 fork 与上游同步"拖累，`patches/` 必须随改随记。

## 明确不做（v1）

- Linux / 移动端
- 图形化 pipeline 编辑
- 云端方案市场、账号、自动更新
- 自定义输入法内核（lua 插件管理可放 v2）
