# ADR-0009 用 git subtree 引入上游，补丁必须登记

- 状态：已接受（2026-11-11）

## 决策
- `platform/macos` ← `rime/squirrel`，`platform/windows` ← `rime/weasel`，通过 `git subtree` 引入。
- 每处本地改动必须在 `patches/` 有对应 `.patch` 文件 + 一段动机说明；CI 校验"工作区差异 ⊂ patches 覆盖范围"（v1 可人工审）。
- 升级流程：`git subtree pull` → 逐条 rebase 补丁 → CI 出双端产物 → 手工冒烟清单。

## 备选与代价
- submodule + 独立仓库：隔离更干净，但改一行业务代码要跨两个仓库提 PR，个人项目过重。
- 直接 fork 仓库再加目录：丢掉"上游可合并"的能力。

## 后果
- 长期维护成本可控；`patches/` 是升级时的唯一真相。
